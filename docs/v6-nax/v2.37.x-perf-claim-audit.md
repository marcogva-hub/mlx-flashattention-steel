# v2.37.x perf claim audit — public API path reachability

**Status:** complete (2026-05-13)
**Author:** CC (institutional-amendment sprint)
**Per:** `CLAUDE_V6_NAX.md` §Z (Public API path testing rule)
**Reference incident:** v2.37.0 / v2.37.1 silent integration bug
(fixed in v2.37.2 via narrow carve-out in `flash_attention()`)

## Audit methodology

Every quantified perf claim in v2.37.x release notes, README, and
`docs/TRAINING_QUICKSTART.md` was reproduced under three conditions:

1. **AUTO path** — `flash_attention(q, k, v)` with default
   `backend="auto"` + `MFA_ENABLE_V34_BACKWARD=1` env var (the
   documented user-facing API setup).
2. **MFA-FORCED path** — `flash_attention(q, k, v, backend="mfa")` +
   same env var (the path V34 backward kernels were originally
   benchmarked against during development; bypasses
   `should_use_mfa()`).
3. **SDPA baseline** — `mx.fast.scaled_dot_product_attention(...)`
   with `mx.grad`; the comparison baseline.

All measurements via canonical methodology (`CLAUDE_V6_NAX.md` §4.2):
4 warmup runs + 12 timed runs, median reported.  M5 Max 128 GB,
macOS 26.4, B=1, H=4, dtype=fp16.

Source: `/tmp/v37x_perf_audit.py` (artifact preserved in this
session's bench traces).

## Claims audited

### v2.37.0 release notes — D=128 "V34 backward 2.2-2.4× slower than SDPA-vjp"

**Documented table** (`docs/releases/v2.37.0-release-notes.md` line 43-46):

| qL | V34 backward | SDPA-vjp | V34 / SDPA |
|---|---|---|---|
| 1024 | 1.07ms | 0.50ms | 2.13× |
| 2048 | 3.22ms | 1.54ms | 2.09× |
| 4096 | 12.77ms | 5.31ms | 2.40× |
| 8192 | 48.93ms | 20.37ms | 2.40× |

**Verdict:** **UNREACHABLE via documented public API path.**

- AUTO-path measurements show V34 does NOT engage for D=128 non-causal
  (ratio 0.98-1.01×, indistinguishable from SDPA-vjp).
- MFA-FORCED measurements DO engage V34: 2.22-2.40× slower, matching
  the documented numbers within methodology floor.
- The release notes do not specify `backend="mfa"` as required.  Users
  following the docs with `MFA_ENABLE_V34_BACKWARD=1` get SDPA-vjp
  silently (post-v2.37.2 fallback at parity; pre-v2.37.2 same
  silent fallback).
- The CLAIM TEXT itself ("V34 backward is 2.2-2.4× slower") is
  truthful at kernel level; it's only the activation path that is
  unspecified.

**Decision:** doc correction (path b).  D=128 V34 backward is
**research infrastructure only** — slower than SDPA-vjp by an
architectural floor, never useful for users.  Auto fallback to
SDPA-vjp is the correct user-facing behavior.  The release-notes
table should be qualified with "(requires `backend='mfa'` — research
characterization, not user-facing)" or moved to research docs.

### v2.37.1 release notes — D=64 "V34 backward 1.4-1.85× FASTER than SDPA-vjp"

**Documented table** (`docs/releases/v2.37.1-release-notes.md` line 39-41):

| qL | V34 backward | SDPA-vjp | V34 / SDPA |
|---|---|---|---|
| 2048 | 0.91ms | 1.31ms | 0.70× (V34 wins 1.44×) |
| 4096 | 2.61ms | 4.81ms | 0.54× (V34 wins 1.85×) |
| 8192 | 9.77ms | 17.69ms | 0.55× (V34 wins 1.81×) |

**Verdicts:**

| qL | AUTO path verdict | MFA-forced verdict | Doc claim accuracy |
|---|---|---|---|
| 2048 | **UNREACHABLE** (1.23× — V34 ran slower) | 0.87× (V34 wins 1.15×, not 1.44×) | OVERSTATED |
| 4096 | **REACHABLE** (0.55× via v2.37.2 carve-out, matches 0.54×) | 0.53× | ACCURATE post-v2.37.2 |
| 8192 | **REACHABLE** (0.55× via v2.37.2 carve-out, matches 0.55×) | 0.55× | ACCURATE post-v2.37.2 |

- The **qL=4096 and qL=8192 claims are reachable** via the public
  AUTO API post-v2.37.2 (carve-out engages V34 for D=64, qL ≥ 4096).
- The **qL=2048 claim is unreachable via AUTO** (carve-out
  threshold is qL ≥ 4096) AND the MFA-forced measurement (0.87×,
  V34 wins 1.15×) is a MUCH smaller win than the 1.44× documented.
  The original v2.37.1 measurement may have come from a different
  B/H/methodology or pre-forward-fusion state — either way, the
  1.44× claim doesn't hold under current canonical methodology.
- End-to-end fwd+bwd at qL=2048: V34 ≈ 1.23+0.77=2.00 ms; SDPA ≈
  1.42+0.70=2.12 ms → V34 wins by 1.06×.  Marginal; below
  measurement-noise threshold.

**Decision:** doc correction (path b).  Update README,
TRAINING_QUICKSTART, and add a v2.37.3 CHANGELOG addendum:
- v2.37.1 qL=2048 claim retracted (was overstated; current bench
  shows 1.15× kernel-level win, ≈parity end-to-end).
- D=64 engagement floor stated as **qL ≥ 4096** (the v2.37.2
  carve-out threshold), not the old "qL ≥ 2048".
- The v2.37.1 release-notes file itself is preserved as historical
  record (do not rewrite history); the v2.37.3 addendum supersedes
  the qL=2048 row.

**Rejected: code fix (path a).**  Extending the v2.37.2 carve-out
down to qL=2048 would add a marginal 1.06× end-to-end win that
falls within methodology noise.  Cost: wider engagement envelope
risks regressions on small-shape inference (V34 forward overhead
0.07-0.13 ms is a larger fraction of total at qL=2048).  Not
worth shipping a code change.

### v2.37.2 release notes — D=64 carve-out "1.81-1.82× faster"

**Documented table** (`docs/releases/v2.37.2-release-notes.md` line 85-86):

| D | qL | V34 backward (carve-out engaged) | SDPA-vjp | Speedup |
|---|----|---|---|---|
| 64 | 4096 | 2.65 ms | 4.83 ms | 1.82× |
| 64 | 8192 | 9.78 ms | 17.67 ms | 1.81× |

**Verdict:** **REACHABLE via public AUTO API.**

- AUTO-path measurements match within 5% of documented numbers
  (2.71 ms / 4.94 ms / 0.55× = 1.82× win at qL=4096; 9.91 ms /
  18.10 ms / 0.55× = 1.83× win at qL=8192).
- v2.37.2 is the first release where the documented claim is
  reachable via the documented API path.

**Decision:** no action.  Claim accurate.

### TRAINING_QUICKSTART.md — D=128 table (mirrors v2.37.0)

**Verdict:** **UNREACHABLE via public AUTO API** — same status as
v2.37.0 D=128 claims (see above).

**Decision:** doc correction.  Update D=128 section to clarify:
- D=128 V34 backward never engages via default `backend="auto"` —
  auto correctly falls back to SDPA-vjp at parity.
- The 2.13-2.40× slowdown numbers are kernel-isolation
  characterizations requiring `backend="mfa"` explicit override.
- Recommendation for D=128 training: stick with default
  `flash_attention(...)` — no env var needed; SDPA-vjp is correct.

## Findings summary

- Claims REACHABLE via public AUTO API: **4 / 11** (v2.37.1 qL=4096,
  v2.37.1 qL=8192, v2.37.2 qL=4096, v2.37.2 qL=8192 — i.e., the
  v2.37.2 carve-out engagement envelope).
- Claims REACHABLE only via `backend="mfa"` forced path:
  **5 / 11** (all D=128 v2.37.0 numbers).  Not user-facing perf;
  kernel-isolation only.
- Claims OVERSTATED at any path: **1 / 11** (v2.37.1 qL=2048 D=64
  "1.44× win" — current bench shows 1.15× kernel-level / 1.06×
  end-to-end win, in measurement noise territory).
- Claims with correct activation: **all post-v2.37.2 entries**.

The audit confirms the v2.37.2 fix achieved its design intent: the
post-fix engagement envelope (D=64, qL ≥ 4096, non-causal, fp16/bf16,
NAX) is the SAME envelope where the perf win is genuinely reachable
via the AUTO API.
