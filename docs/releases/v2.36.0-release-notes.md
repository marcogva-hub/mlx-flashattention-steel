# v2.36.0 — Sprint U: Auto-default principle + transparent optimizations

**Release type**: architectural unification + procedural amendment.
No new kernels; existing optimizations now activate transparently.

## TL;DR

`import mlx_mfa` now installs optimization hooks at import time. M5+ users
get Conv3D NAX (~1.6× on eligible 3×3×3 / 1×1×1 shapes) and the NAX-aware
sparse dispatcher (2.5–4.6× at very-sparse density via `flash_attention_sparse`)
**without writing any mlx-mfa-specific code**.

Pre-v2.36.0, both optimizations required:
- `patch_seedvr2_vae(model)` explicit patcher call for Conv3D NAX
- Calling `sparse_attention_dispatch(...)` directly (the SDPA fallback in
  `flash_attention_sparse` was the only path users hit by default)

v2.36.0 codifies the **auto-default principle**: every PyPI release must
be fully functional transparently for users. Opt-in mechanisms are
transitional (validation pending) or expert-mode (granular control).

## Three usage levels

1. **Default (auto-on-import)** — 90% of users. `import mlx_mfa` and use
   MLX normally. Validated optimizations activate transparently.
2. **Explicit API** — `from mlx_mfa import flash_attention, ...` for direct
   calls when you need control or mlx-mfa-specific features.
3. **Expert mode** — `patch_seedvr2_vae(model)`, `patch_flashvsr_lcsa(model)`
   for per-module granular control + verbose logging.

## Auto-hook details

The hook patches `mx.conv_general`. Eligibility:
- 5-D weight (Conv3D) with kernel shape ∈ {(3,3,3), (1,1,1)}
- dtype ∈ {float16, bfloat16}
- stride == (1,1,1), dilation == (1,1,1), groups == 1, !flip
- M5+ hardware

Ineligible shapes pass through to vanilla MLX unchanged. The check is
the same eligibility logic used by `patch_seedvr2_vae`.

## Sparse attention auto-routing

`flash_attention_sparse` on M5+ with a symmetric BT mask (NQ = qL/BT,
NK = kL/BT, BT ∈ {16, 32, 64}) now auto-routes through
`sparse_attention_dispatch`. The dispatcher routes by density:
- density < 0.02 (DEFAULT_DENSITY_THRESHOLD): Sprint B NAX kernel
- density ≥ 0.02: SDPA + float bias (the v2.35.0 fallback)

Asymmetric STEEL-shape masks (e.g., BQ=32, BK=16) and
`MFA_DISABLE_AUTO_HOOKS=1` paths fall through to the pre-Sprint-U
`_sparse_fallback_sdpa_perhead` behavior.

## Public API additions

```python
import mlx_mfa

mlx_mfa.enable()         # (re-)install hooks; idempotent
mlx_mfa.disable()        # restore vanilla MLX; idempotent
mlx_mfa.hooks_status()   # introspection dict
```

## Escape hatches

```bash
export MFA_DISABLE_AUTO_HOOKS=1   # disables auto-install at import
```

```python
import mlx_mfa
mlx_mfa.disable()        # programmatic uninstall (idempotent)
```

## Backward compatibility

- All v2.35.0 public API signatures preserved.
- Existing `patch_seedvr2_vae(model)` calls continue to work; the
  patcher is now optional for default users but retained for expert
  mode (verbose logging, per-module decisions).
- `MFA_LCSA_KERNEL_VERSION=v2` remains opt-in (sub-1ms methodology
  validation pending). Sprint U makes the future V2-default flip a
  one-line change.
- `flash_attention_sparse(q, k, v, block_mask)` user code continues
  to work; M5+ users now get the NAX-aware dispatch transparently.

## Migration notes for v2.35.x users

1. If you were calling `patch_seedvr2_vae(model)`: code continues to
   work. Optionally remove — `import mlx_mfa` handles it.
2. If you were calling `flash_attention_sparse(...)` on M5+ with a
   symmetric BT mask: expect a perf improvement at very-sparse density
   (NAX-aware dispatcher now engaged). No code change required.
3. If you depend on vanilla MLX for any reason: set
   `MFA_DISABLE_AUTO_HOOKS=1` or call `mlx_mfa.disable()` after import.

## Philosophy: `docs/RELEASE_PHILOSOPHY.md`

The auto-default principle is now canonical:

> Every PyPI release of mlx-mfa must be fully functional transparently
> for users. Validated optimizations activate by default without
> requiring user code changes. Opt-in mechanisms (env vars, named
> patchers) are transitional (validation pending) or expert-mode
> (granular control), never the primary documented user path.

The doc includes the three usage levels, when opt-in is appropriate,
anti-patterns to avoid, and a pre-tag audit checklist (also encoded in
`CLAUDE_V6_NAX.md` §5.X).
