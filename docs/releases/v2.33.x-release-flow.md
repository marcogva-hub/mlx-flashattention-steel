```bash
  "Merge feat/conv-nax-prod: v2.33.0 Conv3D NAX SHIP-DEFAULT"
```

⚠️ **Decision point**: tag at this commit OR continue to v2.33.1 first
without an intermediate v2.33.0 tag?

The v2.33.0 wheel does NOT have the sparse fallback fix (users hit the
2.07× sparse-attention overhead). If you intend to publish both versions
to PyPI as separate releases:
- Tag v2.33.0 here, publish, then continue to Phase 2.

If you only publish v2.33.1 (skipping v2.33.0 as a public release):
- Skip the tag here; merge v2.33.1 patch on top; tag only v2.33.1.

Recommendation: **publish both**. v2.33.0 is the Sprint C/D shipping
milestone; v2.33.1 is a clean follow-up patch. Two-tag pattern matches
mlx-mfa's prior release cadence.

```bash
# Tag v2.33.0
git tag -a v2.33.0 -m "v2.33.0: Conv3D NAX SHIP-DEFAULT (Sprint C+D)

Per docs/conv-nax/ship-shelve-decision.md §10 — median 1.64× speedup
```

## Phase 3 — build + publish

```bash
# Clean build (no editable install, no dev artifacts)
rm -rf build/ dist/ *.egg-info/
.venv/bin/python -m build

# Verify artifacts
ls -la dist/
# Expected:
#   mlx_mfa-2.33.0-cp311-cp311-macosx_26_0_arm64.whl  (if Phase 1 was tagged)
#   mlx_mfa-2.33.0.tar.gz
#   mlx_mfa-2.33.1-cp311-cp311-macosx_26_0_arm64.whl
#   mlx_mfa-2.33.1.tar.gz

# Note: a single `python -m build` only produces the latest version.
# To publish both v2.33.0 and v2.33.1, you have two options:
#
# Option A: build at each tag
#   git checkout v2.33.0 && rm -rf build dist *.egg-info && python -m build
#   git checkout v2.33.1 && rm -rf build dist *.egg-info && python -m build
#
# Option B: skip publishing v2.33.0 to PyPI; only publish v2.33.1.
#   The git tag v2.33.0 is sufficient for GitHub release notes;
#   PyPI users get v2.33.1 (which contains all v2.33.0 changes + the patch).
#
# Recommendation: Option B unless there's a specific reason to publish
# v2.33.0 alone (e.g., a user downstream specifically pinned to 2.33.0).

# Upload to PyPI (Marco's twine credentials configured per usual)
.venv/bin/twine upload dist/mlx_mfa-2.33.1*
```

## Rollback

If a critical bug surfaces after publish:

```bash
# Yank from PyPI (manual via web UI or twine — PyPI yank is one-way:
# users with the version pinned can still install it, but new
# `pip install mlx-mfa` users skip it)

# Delete tag if needed
git tag -d v2.33.1
git push origin :refs/tags/v2.33.1

# Revert merge commit on master (preserves history vs reset)
git revert -m 1 <merge-commit-hash>
git push origin master
```

⚠️ Tag deletion + revert is **disruptive** — only use for critical bugs.
Soft alternative: publish v2.33.2 with the fix.
