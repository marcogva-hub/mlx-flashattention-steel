## What's new for users

### V34 backward eligibility extended to D=64 small-Nk

Previously, D=64 with Nk ≤ 8000 (FlashVSR-class small attention shapes)
fell through to SDPA-vjp.  v2.37.1 adds `force_v34` parameter to
`_ext.v6_nax_forward` so the `flash_attention()` VJP can ensure
natural-log lse is produced even when the default routing would
otherwise pick legacy v6_nax forward (log2-domain lse, incompatible
with V34 backward).

```python
import os
os.environ["MFA_ENABLE_V34_BACKWARD"] = "1"

import mlx.core as mx
import mlx_mfa

# D=64 small-Nk training (was DC12-deferred in v2.37.0):
q = mx.random.normal((1, 4, 512, 64), dtype=mx.float16)
# ... backward routes through V34 NAX kernels now
```

### D=64 large-shape perf WIN

For D=64 training workloads with qL × kL ≥ 4M (= 2048² and above),
**V34 backward is 1.4-1.85× faster than SDPA-vjp** on M5 Max:

| D=64 qL=kL | V34 backward | SDPA-vjp | V34 / SDPA |
|---|---:|---:|---:|
| 2048 | 0.91ms | 1.31ms | 0.70× (V34 wins 1.44×) |
| 4096 | 2.61ms | 4.81ms | 0.54× (V34 wins 1.85×) |
| 8192 | 9.77ms | 17.69ms | 0.55× (V34 wins 1.81×) |

This is a clear perf win for FlashVSR-class and LTX2-style training
workloads.  See `docs/TRAINING_QUICKSTART.md` for shape-aware
recommendation.

### Note on D=128

D=128 V34 backward remains 2.2-2.4× slower than SDPA-vjp.  This is
the architectural floor for the dK kernel at D=128 (extra dO@V^T
matmul scales with D²; D=64 has half the data per fragment, smaller
overhead).  D=128 V34 backward is research infrastructure.
